# System Files Directory

This directory contains system-level configuration files that are layered onto the container image during the build process.

## Directory Structure

The files are organized by build variant:

```
system_files/
├── shared/          # Configuration files used by all variants
├── workstation/     # Desktop-specific (GNOME + KDE + gaming/DX)
├── iot/             # Headless embedded (RPi, Rock5B)
├── k3s/             # Kubernetes cluster nodes
├── handheld/        # Gaming handheld (Gamescope)
└── README.md        # This file
```

## Build Order

Each variant stage copies files in this order:
1. **shared/** — General system configurations applied first
2. **\<variant\>/** — Variant-specific overrides and settings

This ensures that variant-specific settings take precedence over shared defaults.

## File Paths

Configuration files maintain their full system paths:

```
workstation/etc/xdg/kglobalshortcutsrc → /etc/xdg/kglobalshortcutsrc
shared/usr/share/ublue-os/just/...      → /usr/share/ublue-os/just/...
iot/etc/systemd/system/...             → /etc/systemd/system/...
```

## Adding New Configuration Files

When adding a new configuration file:

1. Create the full directory structure under the appropriate variant directory
2. Use the system-absolute path (e.g., `workstation/etc/xdg/kdeglobals`)
3. Add a comment to the file explaining its purpose
4. Test the configuration by building and booting the image

## Variant-Specific Details

### Workstation

Desktop environment configs (GNOME + KDE dual-desktop):

- `workstation/etc/xdg/kglobalshortcutsrc` — Keyboard shortcuts
- `workstation/etc/xdg/kdeglobals` — Global KDE settings

### IoT

Headless embedded configs (RPi, Rock5B):

- Serial console configuration
- Headless service defaults
- Device-tree overlays

### K3s

Kubernetes cluster node configs:

- K3s systemd service overrides
- Cluster networking configuration
- Container runtime settings

### Handheld

Gaming handheld configs (Gamescope):

- Gamescope session configuration
- Input device mapping
- Power management settings

## Testing Configuration Files

To test if your configuration file works:

1. Build the target variant: `podman build --target <variant> -t whiteblossom-<variant>:latest .`
2. Create a disk image: `just build-<type>`
3. Boot: `just run-vm-<type>`
4. Verify the setting is applied

## Notes

- Files are copied using `cp -rT`, preserving directory structure and permissions
- Binary configuration files (like dconf databases) should be generated by scripts, not checked in
- Keep shared configurations minimal to avoid conflicts
- Test all variants when changing shared settings
